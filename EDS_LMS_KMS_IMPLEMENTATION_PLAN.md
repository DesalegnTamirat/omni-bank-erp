# EDS, LMS, KMS audit and implementation plan

Scope: `employee_development_system`, `learning_management`, and `knowledge_management` in `custom_addons`. Review performed 2026-10-12. The findings below drove the implementation in this working tree. Runtime behavior and visual layout still require an Odoo instance.

## Implementation status

- **Implemented in source:** approved-state KMS visibility and protected binary fields; LMS asset field restrictions, an authorized learner document route, and validated completion/exam answers; EDS absence handling; a real, idempotent EDS→LMS course/participant bridge with completion reconciliation; certificate PDF/HR delivery retry status; KMS/LMS lifecycle guards and course revision assessment copies; server-clock-bounded video progress; single KMS download accounting; bounded-memory LMS Range streaming; scoped EDS dashboard counts; and noninteractive KMS metrics. Deprecated Odoo access/read-group calls in these add-ons were updated.
- **Needs Odoo runtime verification:** install/upgrade all three modules, run their existing and new tests, exercise `/web/content` and custom media routes with each role, inspect server warnings, review actual forms on desktop/mobile, and measure large-data queries and concurrent video streams. The local Docker daemon was unavailable during this pass.
- **Remaining product decisions:** real HLS packaging/transcoding (the misleading byte-range manifest now returns 501); whether EDS completion should also create a separate HR development record beyond the existing LMS HR training-history bridge; and whether non-PDF KMS documents need a dedicated protected preview format. These require supported infrastructure or a defined business rule before implementation.

## Priority 0: protect records and completion integrity

1. **KMS: enforce governed document visibility and controlled file access.** The employee rule in `knowledge_management/security/kms_security_rules.xml` allows public/internal classifications without an approved-state condition. The document binary is a readable model field (`models/kms_document.py:114`) and appears as a binary widget (`views/kms_document_views.xml:152`), so the custom download checks can be bypassed through ordinary field reads/attachment delivery. The version model also has employee read access (`security/ir.model.access.csv:15`) without a matching version-specific rule. Put state/classification/ownership policy in record rules and server-side file delivery; restrict direct binary and attachment access, including historical versions. Add tests for draft, review, approved, archived, view-only, group-restricted, and versioned documents via both ORM and HTTP content routes.
2. **LMS: enforce video access at the asset, not only the player route.** Learners have read access to `lms.lesson` (`security/ir.model.access.csv:9`); `video_file` is a readable binary (`models/lms_course.py:238`) in the lesson form (`views/lms_course_views.xml:194`). Guard direct ORM/attachment reads, or move the asset behind a service model whose only learner access is the authorized stream. Exercise unenrolled, locked, unpublished, and expired cases through `/web/content` as well as `/lms/video/...`.
3. **LMS: make completion a validated, idempotent transition.** `models/lms_enrollment.py:242-268` directly marks completion, sets `post_assessment_passed=True`, issues a certificate, and awards points without checking lessons, score, assessment, state, or caller. The learner record rule grants write access. Centralize all gates in the model, protect state/completion fields from direct writes, prevent repeated points and certificates, and test direct RPC/ORM attempts plus the legitimate video/exam paths. Also validate `lms.lesson.progress` direct writes and ownership.
4. **EDS: do not complete absent participants.** `models/eds_session.py:672-701` marks all `enrolled` records completed while only reporting the count with `attended=True`. Define the attendance threshold and disposition for absences, validate attendance before closing, and update each enrollment according to attendance and assessment. Test mixed attendance and certificate eligibility.

## Priority 1: close lifecycle and integration gaps

5. **EDS → LMS routing is a stub.** `models/eds_integration.py:49-60` marks a routing row `synced` and logs success without creating/updating an LMS course or assignment. Implement an explicit bridge (and dependency/integration module as appropriate), persistent remote/local IDs, idempotent upsert, error/retry state, completion feedback, and reconciliation. Acceptance: an EDS e-learning course reaches LMS, an assigned employee can complete it, and the result returns to the EDS/HR development record exactly once.
6. **LMS certificate issuance can leave partial records.** `models/lms_certificate.py:115-158` catches PDF and HR bridge exceptions after issuing a valid certificate, then continues. Define required versus optional side effects; queue retryable jobs for PDF/HR synchronization; surface failure status to managers; reconcile existing partial certificates. Acceptance: issued certificates are downloadable and HR links are complete or visibly pending retry.
7. **KMS workflow must validate state and revision lineage server-side.** `models/kms_document.py:243-365` action methods change states without checking the current state, and approval snapshots the file every invocation. Enforce draft → review → approved → archived transitions, reviewer/manager authority, required metadata, unique version snapshots, and superseding of the prior approved revision. Test repeated calls and concurrent approvals. Apply equivalent state transition checks to LMS course publication (`learning_management/models/lms_course.py:128-168`).
8. **LMS watch-time evidence is client-driven.** `models/lms_enrollment.py:375-409` accepts a client position and adds five watched seconds on every heartbeat, regardless of actual elapsed time; repeated calls can inflate time. Bind progress to server timestamps and bounded monotonic advances; reject malformed values; use the authoritative lesson duration; test rapid/replayed heartbeats and resume behavior. Keep in mind this limits casual abuse but cannot prove attention to a video.

## Priority 2: correctness, performance, and UI

9. **KMS download metrics double count.** `models/kms_document.py:378-402` increments the count and logs a download before returning a URL; `controllers/main.py:103-104` repeats both after serving. Count once after successful delivery, and verify one audit event per download.
10. **KMS search and file processing need scaling limits.** `_search_fts` and `_search_fulltext` in `models/kms_document.py:427-500` materialize IDs in Python and build large `id in` domains; file metadata computation at `:180-205` decodes the entire binary. Bound query results, combine ranking with access filtering, inspect PostgreSQL plans, and read attachment metadata without decoding full files. Add representative-volume benchmarks.
11. **LMS video streaming loads the entire file.** `learning_management/controllers/main.py:67-158` base64-decodes the whole video for both range and manifest responses; range parsing does not validate bounds or return HTTP 416. Use file-backed streaming with bounded memory, proper Range semantics, and media-format-aware delivery. The generated HLS manifest's arbitrary byte ranges should be validated against actual segment boundaries or replaced by a supported streaming format. Benchmark concurrent large videos.
12. **Dashboard queries scale with all records and may disclose totals.** `employee_development_system/models/eds_dashboard.py:98-166` runs many sudo counts and loads all sessions at `:123` to sum enrollments. Replace with grouped aggregates, cache per role where appropriate, and define which global counts each role may see. Test large data sets and non-manager visibility.
13. **KMS stat buttons have no action.** `knowledge_management/views/kms_document_views.xml:103-108` renders Views and Downloads buttons without `name`/`type`; clicking them cannot drill into anything. Link them to filtered audit events or display them as plain metrics. Review labels such as “Download Watermarked PDF” when a non-PDF file is attached, plus responsive layout, keyboard access, contrast, status feedback, empty states, and error messages in each module using actual rendered pages.
